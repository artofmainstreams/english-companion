# AGENTS.md — English Companion

Desktop-приложение для голосовой практики английского: запись речи,
локальное распознавание (STT), диалог с Ollama по выбранному уроку
(системный контекст преподавателя из урока — преподаватель отвечает
только на английском), озвучивание ответов преподавателя
(TTS: Qwen3-TTS (MLX) по умолчанию — голос p4, reference-режим;
macOS `say` — резервный движок).
Python 3.13 + PySide6, MacBook (Apple Silicon); STT — локально
(mlx-whisper по умолчанию, faster-whisper — альтернатива);
Ollama работает на Windows и доступна через SSH-туннель
(http://127.0.0.1:11434).

## Инварианты

- UI остаётся отзывчивым: распознавание — в фоновом потоке,
  аудио — неблокирующе (цикл событий Qt).
- Запись и воспроизведение взаимно исключаются
  (фасад молча отклоняет вторую операцию).
- Аудио удаляется после завершения работы с ним: STT завершает работу
  и освобождает файл, потом рекордер удаляет временные файлы;
  плеер не удаляет пользовательский файл. Синтезатор ответов (TTS) —
  владелец своих временных AIFF и удаляет их в `shutdown()`.
- Ответ преподавателя озвучивается автоматически при добавлении в чат.
  «Повторить ответ» проигрывает ПОСЛЕДНИЙ ГОТОВЫЙ голосовой ответ БЕЗ
  нового запроса к Ollama и без нового синтеза (тот же готовый файл).
  Синтез идёт асинхронно: движок `say` — процесс в цикле событий Qt
  (текст — данные через stdin); движок `qwen3` — фоновый поток модели
  (ленивая загрузка, новый ответ сменяет незавершённый синтез).
  Движок выбирается `config.tts_engine` (по умолчанию `qwen3`,
  reference-режим с референсом p4; `say` — резерв). Референс хранится
  в постоянной папке данных приложения (`app_data.tts_reference_path()`),
  восстановление — `tools/install_tts_reference.py`; при отсутствии
  файла синтез не стартует, а показывает понятную ошибку (проверка —
  до загрузки модели).
- Синтез не блокирует запись/воспроизведение (движок только пишет файл);
  готовый ответ автозапускается только если аудио свободно, иначе ждёт
  ручного «Повторить ответ». Ошибка синтеза оставляет текст в чате и
  показывает понятный статус.
- **Вывод**: по умолчанию у `qwen3` и `say` — полный WAV → QMediaPlayer
  (CoreAudio, ЧИСТО на этой сборке macOS). **Стриминг** (`tts_qwen3_streaming=True`)
  опционален: речь частями через sounddevice/PortAudio — старт быстрее, но
  звучит хрипловато (на этой машине PortAudio искажает речь; тот же клип чистый
  через QMediaPlayer). При стриминге речь стартует ПОСЛЕ накопления стартового
  буфера (`tts_qwen3_start_buffer_ms`), а не сразу на первом куске (защита от
  недочётов). Стриминг недоступен
  ДО звука (фэйк без `.stream` / движок не поддерживает / сбой до первого
  куска) → полный WAV, как раньше. Ошибка ПОСЛЕ начала звука → вывод
  остановлен + понятный статус, БЕЗ автостарта. Stop/новый ответ отменяют
  незавершённый синтез (`cancel()`) — отброшенные куски и WAV НЕ
  публикуются, последний готовый ответ жив для «Повторить ответ».
- STT занятия рассчитан на АНГЛИЙСКУЮ речь: `language="en"` (дефолт),
  `task=transcribe` (расшифровка, НЕ перевод). Адаптеры (mlx-whisper,
  faster-whisper) передают параметры АС-ЕСТЬ из AppConfig, без подмены;
  `language=None` — явное автоопределение (Whisper решает по первому окну
  записи). После STT перевода и LLM-исправлений текста НЕТ.
- **Голосовой ввод — автоматический**: после успешного завершения записи
  (сигнал `recording_completed`) STT запускается сам, а НЕПУСТАЯ расшифровка
  сразу отправляется через `SessionController.send_message` — появляется как
  обычная реплика пользователя. Голосовой ввод **не трогает поле ввода**
  (оно — для ручного текста): при недоступной отправке причина и распознанный
  текст — в строке статуса. Пустой результат / ошибка — НЕ отправляют.
  Один эмит сигнала → одна запись → **максимум одна отправка**. Пока реплика
  обрабатывается (запись/распознавание/ожидание ответа/синтез) — новая
  запись блокируется, после — возвращается.
- **Преподаватель (урок)**: системный контекст собирается из урока
  (level/topics/phrases/words + правила) и передаётся в Ollama вместе
  с историей — ПЕРВЫМ сообщением с ролью `system`, история — после
  него; в чате — ТОЛЬКО реплики пользователя и преподавателя.
  **Учебное поведение**: фразы и слова урока — материал для ПРАКТИКИ
  УЧЕНИКА: преподаватель создаёт поводы их использовать, НЕ читает
  список как свой сценарий и не произносит всё (текущая ситуация
  определяет, какие выражения уместны для каждой роли); реплики
  преподавателя могут включать часть материала, когда это естественно
  для его роли; перед мини-ситуацией — коротко обозначить роли и
  место, роли сохраняются, пока ситуация явно не завершена;
  преподаватель задаёт факты вымышленной ситуации (цены, время
  завтрака, наличие номеров и удобств), вопрос ученику опирается
  ТОЛЬКО на уже сообщённые сведения, его предпочтения или действие,
  которое он может выполнить; «I don't know» — сначала недостающие
  сведения, затем короткая английская подсказка, затем начало фразы,
  затем полный пример, после помощи — ученик пробует сам; практика
  разными способами (ученик задаёт вопросы, выражает пожелания, просит,
  отвечает и уточняет); принимаются подходящие по смыслу
  формулировки. Преподаватель говорит на уровне урока
  (Elementary / Pre-Intermediate / Intermediate / Advanced), ответы
  1–3 предложения, один вопрос за раз, НЕ исправляет мелкие ошибки
  после каждой реплики;
  смысл непонятен — спокойный уточняющий вопрос; спокойный тон, без
  шуток/сарказма, обычный текст — **без эмодзи** и декоративных символов.
  Преподаватель отвечает
  **исключительно на английском**, даже если пользователь пишет/говорит
  по-русски или просит перевод; непонятно — объяснить проще на
  английском (пример/перефразирование); ответ по-русски — мягко
  предложить выразить мысль на английском + подсказка. Голосовой ввод
  занятия рассчитан на английскую речь (`stt_language="en"` по
  умолчанию; `None` — явное автоопределение). «Новое занятие»/смена урока
  = чистая история; непустую историю сбрасывают только после
  подтверждения (отмена — без изменений); действия доступны после
  завершения текущих операций.
- **Перезапись последней реплики**: доступна, пока после этой реплики нет
  следующего сообщения пользователя (ответ преподавателя после неё не
  препятствует). Клик — остановить текущий ответ преподавателя и
  озвучивание, отменить запрос в работе (`discard_pending` →
  `OllamaClient.abort_chat`: поздний результат отбрасывается тихо, ответ
  НЕ перезапускается), затем новая запись. До успешного распознавания
  прежний обмен НЕ трогается; отмена (`cancel_recording` — файл
  отбрасывается, `recording_completed` не поднимается), пустой результат
  или ошибка STT — прежний обмен на месте. Успех: `SessionController`
  заменяет реплику и связанный ответ в `history`, окно перерисовывает
  чат по `history_changed` (история + реплика в работе — единый источник
  правды), запрос уходит с исправленной историей (payload: system +
  история), новый ответ показывается и озвучивается. «Повторить ответ»:
  старый ответ недоступен во время перезаписи и после подтверждённой
  замены (`suppress_reply`); после отмены возвращается, если готовый
  файл сохранился (`unsuppress_reply`); после нового готового ответа
  повтор воспроизводит НОВЫЙ. Сбой нового запроса: исправленная реплика
  сохраняется, повтор — `retry_last_user_message()` БЕЗ дублирования
  реплики в чате. Одна перезапись — максимум одна замена и один новый
  запрос.
- **Содержимое урока**: JSON урока (`phrases`/`words`) — сохраняем
  как есть; полный урок — источник для последующей практики. Если
  большой учебный контекст ухудшает ответы модели — сначала проверяем
  сборку промпта и при необходимости передаём модели подмножество
  материала для текущей ситуации (полный урок остаётся в файле).
  Сокращение содержимого урока в исходном JSON — отдельное решение
  пользователя.
