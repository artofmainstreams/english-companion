# English Companion — текстовый диалог

В активном виртуальном окружении проекта:

```bash
python -m pip install -e .
python main.py
```

Python 3.13, PySide6. Ollama должна быть доступна через существующий
SSH-туннель. Адрес и тайм-ауты — в companion/config.py.

При запуске загружаются модели. Обновление списка сохраняет выбор.
Чат получает полную историю успешных обменов и выбранную модель.
При смене модели история сохраняется. Ответ отображается целиком.
Во время запроса отправка, выбор модели и обновление заблокированы.
При ошибке запрос не входит в контекст; его текст остаётся в видимой
истории, повторная отправка выполняется вручную. История хранится
только в памяти до закрытия приложения. Учебный промпт пока не добавлен.

## Аудио

Кнопки «Записать» и «Прослушать» рядом с чатом: запись речи во
временный файл (M4A, QuickTime или WAV — что поддерживает система)
и воспроизведение последней записи. Во время работы кнопки меняются
на «Остановить»/«Стоп», состояние и ошибки показываются строкой
статуса под чатом. Временные файлы удаляются при закрытии окна;
повторные вызовы и действия после закрытия безопасны.

## Установка обновления

Перенеси main.py, папку companion и pyproject.toml в существующий проект.
Не заменяй свою .venv, .idea, .git и .gitignore. Если менял адрес Ollama,
сохрани его в companion/config.py.

## Проверка вручную

1. Запусти туннель, затем приложение: список моделей появляется сам.
2. Отправь приветствие, затем вопрос о предыдущей реплике.
3. Смени модель: следующий ответ должен иметь её подпись и помнить контекст.
4. Во время генерации убедись, что окно отвечает на перемещение/изменение размера.
5. Отключи туннель и отправь запрос: после ошибки кнопки снова доступны.
6. Восстанови туннель, повтори запрос: успешный ответ продолжает беседу.

## Тесты

Безопасные проверки контроллера аудио — без обращения к устройствам:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Полный прогон: добавляются реальные запись и воспроизведение (нужны
микрофон, звук и разрешения macOS):

```bash
RUN_AUDIO_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Без флага `RUN_AUDIO_TESTS` аудиотесты пропускаются (SKIP) и не
запрашивают устройства. С флагом отсутствие устройства — допустимый
SKIP; отказ записи/воспроизведения после начала сценария, пустой
файл записи и неверное состояние — FAIL.
