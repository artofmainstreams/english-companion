# English Companion — текстовый диалог + локальное распознавание и озвучивание речи

В активном виртуальном окружении проекта:

```bash
# macOS (Apple Silicon) — дефолтный STT-бэкенд MLX:
python -m pip install ".[mlx]"

# TTS: Qwen3-TTS (по умолчанию — включено в основной набор):
python -m pip install ".[qwen3-tts]"

# другие платформы (или альтернатива) — faster-whisper:
python -m pip install ".[faster-whisper]"

# один раз: установить голосовый референс (см. «Озвучивание ответов (TTS)»):
python tools/install_tts_reference.py

python main.py
```

Python 3.13, PySide6, STT: **MLX (mlx-whisper) по умолчанию** или
faster-whisper. TTS: **Qwen3-TTS (MLX) по умолчанию** (голос — референс p4)
или macOS `say` как резервный. Ollama должна быть доступна через существующий
SSH-туннель. Адрес, тайм-ауты, настройки STT и TTS — в companion/config.py.

При запуске загружаются модели. Обновление списка сохраняет выбор.
Чат получает полную историю успешных обменов, выбранную модель и
системный контекст преподавателя из выбранного урока (см.
«Урок и преподаватель»). При смене модели история сохраняется.
Ответ отображается целиком.
Во время запроса отправка, выбор модели и обновление заблокированы.
При ошибке запрос не входит в контекст; его текст остаётся в видимой
истории, повторная отправка выполняется вручную. История хранится
только в памяти до закрытия приложения.

## Урок и преподаватель

Для практики есть уроки. Пока доступен **Урок 12** (id `hw12`, уровень
**Elementary**, «В ресторане») — `lessons/homework12.json`, по
исходнику `raw/homework12_online.doc` (папка `raw/` — только локально,
в Git не попадает).

- Выбор урока — комбо «Урок:» в окне; показывается name и level
  (например, «Урок 12 — Elementary»).
- При отправке сообщения из урока (level, topics, phrases, words)
  собирается системный контекст преподавателя
  (`companion/teacher_context.py`) и передаётся в Ollama **вместе с
  историей разговора** (поле `system` запроса). В чате выводятся только
  реплики пользователя и преподавателя — контекст в историю не входит.
- Правила преподавателя (в системном контексте): речь соответствует
  уровню урока (Elementary / Pre-Intermediate / Intermediate / Advanced);
  ответы короткие — обычно 1–3 предложения; один вопрос за раз;
  естественная беседа с возможностями использовать темы, слова и фразы
  урока; принимаются подходящие по смыслу варианты ответа, даже если
  они отличаются от фраз урока; небольшие ошибки не исправляются после
  каждой реплики; смысл непонятен — уточняющий вопрос. Преподаватель
  отвечает **исключительно на английском**, даже если пользователь
  пишет или говорит по-русски или просит перевод; если не понимает —
  объяснить проще на английском (короткий пример или перефразирование);
  ответил по-русски — мягко предложить выразить мысль на английском и
  дать английскую подсказку. STT продолжает распознавать исходный язык
  пользователя (правило касается только ответов преподавателя).
- **«Новое занятие»** начинает разговор с чистой историей и выбранным
  уроком. Если история непустая — запрашивается подтверждение сброса
  (отмена — ничего не меняется). Смена урока тоже оформляется как
  начало нового занятия с подтверждением. Действия доступны после
  завершения текущих операций (отправка/распознавание/синтез/аудио).
- Если урок не загрузился — понятная ошибка в строке статуса,
  отправка недоступна.

Формат урока (`companion/lesson.py`): `id` (непустая строка), `level`
(Elementary \| Pre-Intermediate \| Intermediate \| Advanced), `name`
(непустая строка, например «Урок 12»), `topics` (темы и конструкции,
хотя бы одна), `phrases` и `words` — списки строк (могут быть пустыми).

### Ручная проверка (ресторанная тема, несколько реплик)

1. Запусти туннель и приложение; в «Урок:» стоит «Урок 12 — Elementary».
2. Отправь пару реплик по теме: «I'd like a table for two»,
   «What do you recommend for a main course?» — ответы короткие
   (1–3 предложения), Elementary-словарь, один вопрос за раз.
3. Напиши по-русски (например, «сколько стоит бутылка воды?») —
   преподаватель продолжает отвечать только по-английски и мягко
   подталкивает к английскому.
4. При непустой истории нажми «Новое занятие»: подтверди — история
   очищена; отмени — история сохранена.

## Аудио

Кнопки «Записать» и «Прослушать» рядом с чатом: запись речи во
временный файл (M4A, QuickTime или WAV — что поддерживает система)
и воспроизведение последней записи. Во время работы кнопки меняются
на «Остановить»/«Стоп», состояние и ошибки показываются строкой
статуса под чатом. Временные файлы удаляются при закрытии окна;
повторные вызовы и действия после закрытия безопасны.

## Озвучивание ответов (TTS)

Ответ преподавателя озвучивается локально, без нового запроса к Ollama:

1. Ollama возвращает ответ → текст сразу виден в чате.
2. Приложение синтезирует текст в WAV-файл движком из
   `AppConfig.tts_engine`:
   * **`qwen3` — по умолчанию**: Qwen3-TTS (MLX), режим **reference**:
     Base-модель `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16` клонирует
     голос по референсу — реплика p4 одобренного голоса D
     (`tts_qwen3_ref_audio` + её точный текст `tts_qwen3_ref_text`).
     Синтез — в фоновом потоке (UI не блокируется); модель грузится
     лениво на первом ответе (входит в задержку первого ответа), далее
     переиспользуется. Выбор голоса D и p4-референса — см. раздел
     «Сохранность выбранного голоса D…»;
   * `say` — резервный: macOS `say` (английский голос из
     `AppConfig.tts_voice`, по умолчанию `Samantha`), процесс в цикле
     событий Qt, текст — данные через stdin.
3. После успешного создания временного WAV файл отдаётся существующему
   `AudioPlayer` (QMediaPlayer декодирует WAV/AIFF — проверено на
   целевой сборке Qt до `EndOfMedia`).
4. Готовый ответ автозапускается только если аудио свободно. Если аудио
   занято (идёт запись или воспроизведение), ответ сохраняется и ждёт
   ручного повтора.

### Потоковый вывод (речь частями; `qwen3` по умолчанию)

Чтобы первый звук появился раньше, чем синтезится весь WAV, `qwen3`
ведёт речь ПОТОКОМ (по умолчанию включено; `say` — весь WAV, как раньше):

* движок синтезирует кусками
  (`model.generate(..., stream=True, streaming_interval=…)`), сигнал
  `chunk_ready(chunk, sr, job_id)`;
* вывод идёт через `sounddevice` (PortAudio) — `QAudioSink` в этой сборке
  PySide6 не даёт писать куски (нет `write`/`bufferedAmount`);
* речь стартует, когда накоплен **стартовый буфер**
  (`tts_qwen3_start_buffer_ms`, по умолчанию 500 мс) — защита от недочётов
  на старте;
* полный WAV собирается из тех же кусков — «Повторить ответ» проигрывает
  тот же готовый файл БЕЗ повторного синтеза;
* стриминг недоступен ДО звука (движок не поддерживает / сбой до первого
  куска) → полный WAV, как раньше; ошибка ПОСЛЕ начала звука → вывод
  остановлен + понятный статус, без автостарта; Stop и новый ответ
  отменяют незавершённый синтез (`cancel()`), последний готовый ответ
  сохраняется.

Настройки в `companion/config.py`: `tts_qwen3_streaming` (**вкл**),
`tts_qwen3_streaming_interval` (0.5 с), `tts_qwen3_start_buffer_ms` (500 мс).

Кнопка **«Повторить ответ»** проигрывает последний готовый голосовой
ответ БЕЗ нового запроса к Ollama и без нового синтеза (тот же готовый
файл). Кнопка доступна, только если есть готовый ответ и аудио свободно.

### Файл референса голоса и его восстановление

Файл референса живёт в **постоянной папке данных приложения** (не в
репозитории и не в .venv), на macOS это
`~/Library/Application Support/english-companion/tts/qwen3_p4_ref.wav`
(путь задаётся `companion/app_data.py`; исходник —
`~/Desktop/qwen-voice-low-register/qwen3_D_vd_p4.wav`).

После переустановки окружения или переноса проекта восстанови его один раз:

```bash
.venv/bin/python tools/install_tts_reference.py
# свой исходный файл:
.venv/bin/python tools/install_tts_reference.py /путь/к/ref.wav
```

Если файла нет, синтез НЕ запускается «вслепую»: приложение показывает
понятную ошибку («референс голоса не найден: … — восстанови файл
`tools/install_tts_reference.py`»), текст ответа остаётся в чате.
Проверка наличия файла — ДО загрузки модели (тест работает офлайн).

Поведение при проблемах:
- ошибка синтеза оставляет текст ответа доступным в чате и показывает
  понятный статус в строке «Голос»; частичный файл удаляется;
- при закрытии окна синтез (процесс `say` / фоновый поток модели)
  останавливается и плеер останавливается ДО удаления временных файлов;
  повторные вызовы безопасны; закрытие ВО ВРЕМЯ синтеза проверено
  (без зависаний: «ожидание» потока ограничено, поздний результат
  отбрасывается, слой не «оживает»).

Слышимость и качество голоса — ручная проверка (см. «Проверка вручную»
и «Реальная многоцикловая проверка»).

## Распознавание речи (STT)

Голосовой ввод автоматический: записать → «Остановить» → распознавание
запускается **само** по только что завершённой записи (сигнал
`recording_completed`) → **непустая расшифровка сразу отправляется** через
`SessionController.send_message` (появляется как обычная реплика
пользователя). Голосовой ввод **не трогает поле ввода** (оно — для ручного
текста): при недоступной отправке причина и распознанный текст показываются
в строке статуса. Пустой результат или ошибка — **ничего не отправляется**.
Одна запись — максимум одна отправка. Пока реплика обрабатывается, новая
запись блокируется.

- Распознавание идёт локально. Бэкенд выбирается в `AppConfig.stt_backend`:
  - `mlx` — **по умолчанию**: mlx-whisper, модель
    `mlx-community/whisper-large-v3-mlx` (fp16, мультиязычная), macOS arm64;
  - `faster-whisper` — альтернатива, выбирается явно: `base`
    (мультиязычная модель: авто-определение языка работает и для русского;
    `.en`-модели — только английский), `device=cpu`, `compute_type=int8`,
    `vad_filter=True`.
  - Общие параметры: `language=None` — **язык определяется автоматически**
    (русский -> русский текст, английский -> английский); язык можно
    зафиксировать явно (`stt_language="en"`/`"ru"`), `task=transcribe`
    (расшифровка, не перевод). Никакого перевода и LLM-исправления текста —
    только распознавание.
  - **Автоматического fallback нет**: неизвестный бэкенд или отсутствующие
    зависимости — понятная ошибка с подсказкой, а не тихая смена движка.
- Модель грузится **лениво один раз** и переиспользуется. Загрузка модели и
  само распознавание выполняются в фоновом потоке, а не в UI.
- **Первая загрузка весов требует интернета**; веса кэшируются (вне проекта,
  не попадают в Git), дальше распознавание полностью локальное.
- MLX-бэкенд требует **системный ffmpeg** в PATH (mlx-whisper декодирует
  аудио подпроцессом; проверка: `command -v ffmpeg`).
- Закрытие окна во время распознавания **откладывается** (окно остаётся
  отзывчивым, блокирующий join в UI-потоке не выполняется); файл записи
  удаляется только после завершения распознавания.
- Показываются состояния: «Загружаю модель…», «Распознаю речь…», ошибки.
- Пока голосовая реплика обрабатывается (распознавание, ожидание ответа,
  синтез, воспроизведение) — новая запись заблокирована; исходный аудиофайл
  не удаляется до завершения работы, после — запись снова доступна.
- Голосовой ввод не трогает поле ввода (оно — для ручного текста): набранный
  вручную текст не затирается; при недоступной отправке причина и
  распознанный текст показываются в строке статуса; пустой результат / ошибка
  — ничего не отправляется.

## Установка обновления

Перенеси main.py, папку companion, pyproject.toml, real_stt_check.py,
real_tts_check.py, папки tools и tests в существующий проект. Не заменяй
свою .venv, .idea, .git и .gitignore. Если менял адрес Ollama или настройки
STT/TTS, сохрани их в companion/config.py (теперь это поля `stt_backend`,
`stt_mlx_model`, `stt_whisper_model`, `tts_engine`, `tts_qwen3_*` и т.д.).
После переноса установи нужные группы бэкендов:
`python -m pip install ".[mlx]"`, `".[qwen3-tts]"` и/или
`".[faster-whisper]"`, затем один раз восстанови голосовой референс
(см. «Файл референса голоса и его восстановление»). Референс лежит в
постоянной папке данных приложения и переживает переустановку кода —
в отличие от весов и экспериментальных WAV (те — вне проекта).

## Проверка вручную

1. Запусти туннель, затем приложение: список моделей появляется сам.
2. Отправь приветствие, затем вопрос о предыдущей реплике.
3. Смени модель: следующий ответ должен иметь её подпись и помнить контекст.
4. Во время генерации убедись, что окно отвечает на перемещение/изменение размера.
5. Отключи туннель и отправь запрос: после ошибки кнопки снова доступны.
6. Восстанови туннель, повтори запрос: успешный ответ продолжает беседу.
7. Отправь вопрос: ответ появляется в чате и озвучивается голосом
   преподавателя (по умолчанию Qwen3-TTS, голос p4 — слушай тембр,
   акцент и естественность: это проверяется ТОЛЬКО на слух);
   «Повторить ответ» проигрывает ту же реплику без нового запроса
   и без нового синтеза.
8. Пока идёт воспроизведение ответа, запись отклоняется (аудио занято);
   после «Стоп» «Повторить ответ» снова проигрывает готовую реплику.
9. Первый ответ после запуска синтезится дольше (загрузка модели
   Qwen3 входит в задержку); последующие — быстрее.
10. Закрой приложение, пока идёт синтез: окно закрывается без зависаний,
   поздний синтез не «пробивается» после закрытия.
11. Голосовой ввод: «Записать» → говори → «Остановить» — распознавание
   запускается само, а непустая расшифровка сразу уходит в чат как твоя
   реплика (поле ввода при этом **не трогается** — оно для ручного текста), после чего ответ преподавателя
   озвучивается. Пока идёт распознавание/ответ — «Записать» заблокирован;
   после — снова доступен. Пустая или ошибочная расшифровка ничего не
   отправляет. (Ручная приёмка: один обмен с микрофона + одно текстовое
   сообщение.)

## Тесты

Безопасные проверки — контроллера аудио, TTS (подменённый синтез)
и STT (подменённая модель). Не требуют микрофона, интернета и
скачивания веса:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Полный прогон: добавляются реальные запись и воспроизведение (нужны
микрофон, звук и разрешения macOS):

```bash
RUN_AUDIO_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Без флага `RUN_AUDIO_TESTS` аудиотесты пропускаются (SKIP) и не
запрашивают устройства. С флагом отсутствие устройства — допустимый
SKIP; отказ записи/воспроизведения после начала сценария, пустой
файл записи и неверное состояние — FAIL.

STT-тесты окна (подмены; без микрофона и сети) проверяют: успешная запись
→ авто-STT → автоотправка (реплика в чате; поле ввода не тронуто); пустой
результат / ошибка (ничего не отправлено, поле ввода не тронуто); один эмит
сигнала — одна отправка (без дублей); отправка недоступна (поле ввода не
тронуто, причина — в строке статуса); блокировка записи, пока идёт
распознавание/ожидание ответа, и её возврат; отложенное закрытие окна.

Тесты урока и преподавателя (`tests/test_lesson_session.py`, клиент
Ollama подменён — без сети) проверяют: сборку системного контекста из
урока (level/topics/phrases/words + правила преподавателя, «только
английский») и его передачу в Ollama (поле `system`); в чате — только
реплики пользователя и преподавателя; «Новое занятие» — сброс непустой
истории только с подтверждением (отмена — без изменений), смена урока =
новое занятие с подтверждением; действия заблокированы, пока идёт
операция; сбой загрузки урока — понятная ошибка и отправка недоступна.
Загрузка и валидация самого JSON — `tests/test_lesson.py` (корректный
урок + понятные ошибки для отсутствующих/неверных полей).

TTS-тесты (на подменах, без реального `say`/Qwen3 и устройств звука)
проверяют для ОБОХ движков (`tests/test_tts_reply.py` — `say`,
`tests/test_tts_qwen3.py` — Qwen3): успешный ответ (готовый файл,
автозапуск при свободном аудио), смену незавершённого синтеза,

## Реальная многоцикловая проверка (TTS + полный цикл)

`real_tts_check.py` — явная проверка ПОЛОГО цикла в ОДНОМ запуске

```bash

```

Замеряет ОТДЕЛЬНО для первого и последующих ответов: время

результат отбрасывается, слой не «оживает».

Оговорки (проверена МЕХАНИКА, а не «живой» сценарий):
* «запись» — готовый файл английской речи (по умолчанию macOS `say`

* что проверено АВТОМАТИЧЕСКИ: пайплайн, сигналы, состояния, файл,
  повтор, порядок shutdown, времена;
* что проверяешь ТОЛЬКО ты, НА СЛУХ: тембр/акцент/естественность голоса

## Замер задержки короткого ответа по этапам + стриминг TTS

Два диагностических запуска (всё настоящее: STT/Ollama/TTS p4; «речь
студента» — готовый аудио macOS `say`, «ожидание отправки» — имитация
паузы пользователя):

* `real_tts_latency.py` — 5 коротких циклов в ОДНОМ запуске; отдельно
  показывает STT (распознавание), ожидание ручной отправки, Ollama,
  загрузку TTS (только первый цикл), синтез TTS и запуск плеера;
  TTS-этап синтезирует ОДИНАКОВЫЙ короткий текст, чтобы первый вызов
  (загрузка + синтез) был сравним с повторными (синтез на загруженной
  модели). Итог: где именно живая задержка до первого слова.
* `real_tts_stream_trial.py` — пробный СТРИМИНГ Qwen3 (reference, p4):
  речь частями через `generate(..., stream=True)`, реальное воспроизведение
  `sounddevice`. Меряет time-to-first-sound (TTFS) и разрывы (underrun)
  при разных `streaming_interval`, и сравнивает с текущим «весь WAV».
 * `real_tts_stream_app.py` — стриминг в ПРИЛОЖЕНИИ (настоящие
   `AudioController` + `Qwen3TtsSynth` + воспроизведение `sounddevice`,
   звук слышен): сравнение «весь WAV» vs стриминг на одинаковых текстах
   (короткий/длинный; TTFC, старт вывода, недочёты, RTF), подбор стартового
   буфера (500 vs 1000 мс), Stop/новый ответ/закрытие во время синтеза
   (факт смерти потока, отдельно от `join(timeout)`), полный голосовой цикл
   (STT + пауза ручной отправки [имитация] + Ollama + TTS). Нужен туннель
   Ollama.

```bash
.venv/bin/python real_tts_latency.py
.venv/bin/python real_tts_stream_trial.py
.venv/bin/python real_tts_stream_app.py
```

Результат (M1, Ollama `qwen3.8-27b-64k`, голос p4): короткое ответное
аудио ~2.9 с. Задержка короткого ответа (модель загружена) в среднем:
TTS-синтез ~3.5 с, STT ~2.4 с, Ollama ~2.3 с, ожидание отправки ~1.5 с
(имитация), запуск плеера 0.0 с. Стриминг сокращает TTFS с ~4.3 с
(весь WAV) до 0.55–0.72 с (interval 0.3–0.5 с) БЕЗ разрывов — генерация
в стриминге быстрее реального времени (RTF ~1.15–1.18).

Оговорки: TTFS стриминга меряется до СТАРТА воспроизведения первого куска
(до физического звука — ещё десятки мс); тембр/естественность и
слышимость швов между кусками проверяешь на слух ты.

### Интеграция Qwen3-TTS в приложение (подключена, по умолчанию включена)
