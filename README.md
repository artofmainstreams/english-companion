# English Companion — текстовый диалог + локальное распознавание и озвучивание речи

В активном виртуальном окружении проекта:

```bash
# macOS (Apple Silicon) — дефолтный STT-бэкенд MLX:
python -m pip install ".[mlx]"

# TTS: Qwen3-TTS (по умолчанию — включено в основной набор):
python -m pip install ".[qwen3-tts]"

# другие платформы (или альтернатива) — faster-whisper:
python -m pip install ".[faster-whisper]"

# один раз: установить голосовый референс (см. «Озвучивание ответов (TTS)»):
python tools/install_tts_reference.py

python main.py
```

Python 3.13, PySide6, STT: **MLX (mlx-whisper) по умолчанию** или
faster-whisper. TTS: **Qwen3-TTS (MLX) по умолчанию** (голос — референс p4)
или macOS `say` как резервный. Ollama должна быть доступна через существующий
SSH-туннель. Адрес, тайм-ауты, настройки STT и TTS — в companion/config.py.

При запуске загружаются модели. Обновление списка сохраняет выбор.
Чат получает полную историю успешных обменов и выбранную модель.
При смене модели история сохраняется. Ответ отображается целиком.
Во время запроса отправка, выбор модели и обновление заблокированы.
При ошибке запрос не входит в контекст; его текст остаётся в видимой
истории, повторная отправка выполняется вручную. История хранится
только в памяти до закрытия приложения. Учебный промпт пока не добавлен.

## Аудио

Кнопки «Записать» и «Прослушать» рядом с чатом: запись речи во
временный файл (M4A, QuickTime или WAV — что поддерживает система)
и воспроизведение последней записи. Во время работы кнопки меняются
на «Остановить»/«Стоп», состояние и ошибки показываются строкой
статуса под чатом. Временные файлы удаляются при закрытии окна;
повторные вызовы и действия после закрытия безопасны.

## Озвучивание ответов (TTS)

Ответ преподавателя озвучивается локально, без нового запроса к Ollama:

1. Ollama возвращает ответ → текст сразу виден в чате.
2. Приложение синтезирует текст в WAV-файл движком из
   `AppConfig.tts_engine`:
   * **`qwen3` — по умолчанию**: Qwen3-TTS (MLX), режим **reference**:
     Base-модель `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-bf16` клонирует
     голос по референсу — реплика p4 одобренного голоса D
     (`tts_qwen3_ref_audio` + её точный текст `tts_qwen3_ref_text`).
     Синтез — в фоновом потоке (UI не блокируется); модель грузится
     лениво на первом ответе (входит в задержку первого ответа), далее
     переиспользуется. Выбор голоса D и p4-референса — см. раздел
     «Сохранность выбранного голоса D…»;
   * `say` — резервный: macOS `say` (английский голос из
     `AppConfig.tts_voice`, по умолчанию `Samantha`), процесс в цикле
     событий Qt, текст — данные через stdin.
3. После успешного создания временного WAV файл отдаётся существующему
   `AudioPlayer` (QMediaPlayer декодирует WAV/AIFF — проверено на
   целевой сборке Qt до `EndOfMedia`).
4. Готовый ответ автозапускается только если аудио свободно. Если аудио
   занято (идёт запись или воспроизведение), ответ сохраняется и ждёт
   ручного повтора.

Кнопка **«Повторить ответ»** проигрывает последний готовый голосовой
ответ БЕЗ нового запроса к Ollama и без нового синтеза (тот же готовый
файл). Кнопка доступна, только если есть готовый ответ и аудио свободно.

### Файл референса голоса и его восстановление

Файл референса живёт в **постоянной папке данных приложения** (не в
репозитории и не в .venv), на macOS это
`~/Library/Application Support/english-companion/tts/qwen3_p4_ref.wav`
(путь задаётся `companion/app_data.py`; исходник —
`~/Desktop/qwen-voice-low-register/qwen3_D_vd_p4.wav`).

После переустановки окружения или переноса проекта восстанови его один раз:

```bash
.venv/bin/python tools/install_tts_reference.py
# свой исходный файл:
.venv/bin/python tools/install_tts_reference.py /путь/к/ref.wav
```

Если файла нет, синтез НЕ запускается «вслепую»: приложение показывает
понятную ошибку («референс голоса не найден: … — восстанови файл
`tools/install_tts_reference.py`»), текст ответа остаётся в чате.
Проверка наличия файла — ДО загрузки модели (тест работает офлайн).

Поведение при проблемах:
- ошибка синтеза оставляет текст ответа доступным в чате и показывает
  понятный статус в строке «Голос»; частичный файл удаляется;
- при закрытии окна синтез (процесс `say` / фоновый поток модели)
  останавливается и плеер останавливается ДО удаления временных файлов;
  повторные вызовы безопасны; закрытие ВО ВРЕМЯ синтеза проверено
  (без зависаний: «ожидание» потока ограничено, поздний результат
  отбрасывается, слой не «оживает»).

Слышимость и качество голоса — ручная проверка (см. «Проверка вручную»
и «Реальная многоцикловая проверка»).

## Распознавание речи (STT)

Кнопка «Распознать» рядом с «Записать»/«Прослушать». Сценарий:
записать → остановить → «Распознать» → распознанный текст попадает в поле
ввода → отправить вручную (ничего не отправляется автоматически).

- Распознавание идёт локально. Бэкенд выбирается в `AppConfig.stt_backend`:
  - `mlx` — **по умолчанию**: mlx-whisper, модель
    `mlx-community/whisper-large-v3-mlx` (fp16, мультиязычная), macOS arm64;
  - `faster-whisper` — альтернатива, выбирается явно: `base`
    (мультиязычная модель: авто-определение языка работает и для русского;
    `.en`-модели — только английский), `device=cpu`, `compute_type=int8`,
    `vad_filter=True`.
  - Общие параметры: `language=None` — **язык определяется автоматически**
    (русский -> русский текст, английский -> английский); язык можно
    зафиксировать явно (`stt_language="en"`/`"ru"`), `task=transcribe`
    (расшифровка, не перевод). Никакого перевода и LLM-исправления текста —
    только распознавание.
  - **Автоматического fallback нет**: неизвестный бэкенд или отсутствующие
    зависимости — понятная ошибка с подсказкой, а не тихая смена движка.
- Модель грузится **лениво один раз** и переиспользуется. Загрузка модели и
  само распознавание выполняются в фоновом потоке, а не в UI.
- **Первая загрузка весов требует интернета**; веса кэшируются (вне проекта,
  не попадают в Git), дальше распознавание полностью локальное.
- MLX-бэкенд требует **системный ffmpeg** в PATH (mlx-whisper декодирует
  аудио подпроцессом; проверка: `command -v ffmpeg`).
- Закрытие окна во время распознавания **откладывается** (окно остаётся
  отзывчивым, блокирующий join в UI-потоке не выполняется); файл записи
  удаляется только после завершения распознавания.
- Показываются состояния: «Загружаю модель…», «Распознаю речь…», ошибки.
- Во время распознавания заблокированы повторный запуск и новая запись;
  исходный аудиофайл не удаляется до завершения работы.
- Введённый текст не перезаписывается молча: если поле не пустое —
  запрашивается подтверждение замены; пустой результат не стирает поле.

## Установка обновления

Перенеси main.py, папку companion, pyproject.toml, real_stt_check.py,
real_tts_check.py, папки tools и tests в существующий проект. Не заменяй
свою .venv, .idea, .git и .gitignore. Если менял адрес Ollama или настройки
STT/TTS, сохрани их в companion/config.py (теперь это поля `stt_backend`,
`stt_mlx_model`, `stt_whisper_model`, `tts_engine`, `tts_qwen3_*` и т.д.).
После переноса установи нужные группы бэкендов:
`python -m pip install ".[mlx]"`, `".[qwen3-tts]"` и/или
`".[faster-whisper]"`, затем один раз восстанови голосовой референс
(см. «Файл референса голоса и его восстановление»). Референс лежит в
постоянной папке данных приложения и переживает переустановку кода —
в отличие от весов и экспериментальных WAV (те — вне проекта).

## Проверка вручную

1. Запусти туннель, затем приложение: список моделей появляется сам.
2. Отправь приветствие, затем вопрос о предыдущей реплике.
3. Смени модель: следующий ответ должен иметь её подпись и помнить контекст.
4. Во время генерации убедись, что окно отвечает на перемещение/изменение размера.
5. Отключи туннель и отправь запрос: после ошибки кнопки снова доступны.
6. Восстанови туннель, повтори запрос: успешный ответ продолжает беседу.
7. Отправь вопрос: ответ появляется в чате и озвучивается голосом
   преподавателя (по умолчанию Qwen3-TTS, голос p4 — слушай тембр,
   акцент и естественность: это проверяется ТОЛЬКО на слух);
   «Повторить ответ» проигрывает ту же реплику без нового запроса
   и без нового синтеза.
8. Пока идёт воспроизведение ответа, запись отклоняется (аудио занято);
   после «Стоп» «Повторить ответ» снова проигрывает готовую реплику.
9. Первый ответ после запуска синтезится дольше (загрузка модели
   Qwen3 входит в задержку); последующие — быстрее.
10. Закрой приложение, пока идёт синтез: окно закрывается без зависаний,
   поздний синтез не «пробивается» после закрытия.

## Тесты

Безопасные проверки — контроллера аудио, TTS (подменённый синтез)
и STT (подменённая модель). Не требуют микрофона, интернета и
скачивания веса:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Полный прогон: добавляются реальные запись и воспроизведение (нужны
микрофон, звук и разрешения macOS):

```bash
RUN_AUDIO_TESTS=1 .venv/bin/python -m unittest discover -s tests -v
```

Без флага `RUN_AUDIO_TESTS` аудиотесты пропускаются (SKIP) и не
запрашивают устройства. С флагом отсутствие устройства — допустимый
SKIP; отказ записи/воспроизведения после начала сценария, пустой
файл записи и неверное состояние — FAIL.

STT-тесты проверяют: успех (текст в поле), пустой результат (поле не
стёрто), ошибку (поле не стёрто), блокировку повторного запуска,
сохранность введённого текста и подтверждение замены, отложенное
закрытие окна.

TTS-тесты (на подменах, без реального `say`/Qwen3 и устройств звука)
проверяют для ОБОХ движков (`tests/test_tts_reply.py` — `say`,
`tests/test_tts_qwen3.py` — Qwen3): успешный ответ (готовый файл,
автозапуск при свободном аудио), смену незавершённого синтеза,
«Повторить ответ» без нового синтеза, ошибку синтеза (нет автозапуска,
понятный статус, частичный файл удалён, текст остаётся в чате),
занятое аудио (ответ сохраняется для ручного повтора), закрытие во
время синтеза (поток остановлен, файлы удалены, слой не «оживает»).
Отдельно: отсутствие файла референса (Qwen3 reference) — понятная ошибка
«референс голоса не найден…» ДО загрузки модели (тест офлайн, без
mlx-audio) и выбор движка в `build_tts` (по умолчанию `qwen3`/
`reference` + референс из папки данных приложения; `reference` без пары
«файл + текст» — явная ошибка).

MLX-путь (по умолчанию) покрыт отдельным набором `tests/test_stt_engine_mlx.py`:
обычный запуск, повторное использование модели (загрузка один раз),
ошибки и отсутствие автоматического fallback (неизвестный бэкенд —
`ValueError`; отсутствующие mlx/mlx-whisper — понятная ошибка с
подсказкой по установке). Всё на подменах: без весов, интернета и микрофона.

## Реальное распознавание (отдельная проверка)

Реальное распознавание на настоящей модели запускается явно. По умолчанию
проверяется бэкенд из AppConfig (MLX large-v3); альтернативу выбирают
флагом. Замеряет загрузку модели отдельно от повторного распознавания.
Первый запуск скачивает веса (нужен интернет), далее локально:

```bash
# Дым-тест пайплайна (генерирует тон; речь не распознается — пусто):
.venv/bin/python real_stt_check.py

# С твоим файлом речи:
.venv/bin/python real_stt_check.py путь/к/записи.m4a

# Альтернативный бэкенд:
.venv/bin/python real_stt_check.py --backend faster-whisper
```

## Реальная многоцикловая проверка (TTS + полный цикл)

`real_tts_check.py` — явная проверка ПОЛОГО цикла в ОДНОМ запуске
приложения (без GUI-кликов, но с настоящими компонентами):
реальный STT (mlx-whisper) → реальный запрос Ollama (`OllamaClient`) →
реальный синтез (`build_tts(AppConfig())`, Qwen3 reference, голос p4) →
реальное воспроизведение (звук слышен) → «Повторить ответ» → второй
цикл → закрытие во время синтеза.

```bash
.venv/bin/python real_tts_check.py
.venv/bin/python real_tts_check.py --audio ~/Desktop/запись.m4a
.venv/bin/python real_tts_check.py --cycles 3
```

Замеряет ОТДЕЛЬНО для первого и последующих ответов: время
«текст → звук» (от получения ответа Ollama до входа плеера в PLAYING),
время синтеза, время STT/Ollama. Проверяет: повтор — тот же файл и без
нового синтеза; закрытие во время синтеза — без зависаний, поздний
результат отбрасывается, слой не «оживает».

Оговорки (проверена МЕХАНИКА, а не «живой» сценарий):
* «запись» — готовый файл английской речи (по умолчанию macOS `say`
  генерирует), НЕ запись с микрофона;
* что проверено АВТОМАТИЧЕСКИ: пайплайн, сигналы, состояния, файл,
  повтор, порядок shutdown, времена;
* что проверяешь ТОЛЬКО ты, НА СЛУХ: тембр/акцент/естественность голоса
  и совпадение его с одобренным образцом p4.

Результат прогона (M1, Ollama `qwen3.8-27b-64k`, 2 цикла): STT
5.49 с (вкл. загрузку) / 4.41 с; Ollama 6.62 / 2.90 с; первый ответ
текст→звук 28.89 с (синтез вкл. загрузку модели), последующий 17.69 с
(длина ответов ~22 с аудио); повтор — тот же файл, 0 новых синтезов;
закрытие во время синтеза — все 6 проверок OK, `shutdown()` вернулась
за 5.01 с (ограничение join 5 с).

## Подбор голоса TTS: Kokoro-82M и Qwen3-TTS VoiceDesign (MLX)

Эксперимент для выбора голоса преподавателя (британское произношение,
молодой женский тембр). Пока выбор не сделан, TTS приложения НЕ меняется:
ответы озвучивает macOS `say` с `Samantha` (`companion/tts_synth.py`,
`AppConfig.tts_voice`).

`tools/kokoro_voice_samples.py` генерирует по одному WAV на голос
(по умолчанию 4 учебные фразы, одинаковый темп `--speed 1.0`, пауза
0.6 c между репликами) и, с `--with-say`, образец `say` на тех же фразах.
Образцы пишутся в `--out` (по умолчанию `~/Desktop/kokoro-voices`) —
ВНЕ репозитория и не попадают в Git; как и веса модели.

Эксперимент работает в отдельном временном окружении, НЕ в .venv
проекта (рабочее окружение Python 3.13 проекта не меняется):

```bash
# окружение (уже создано при проверке; путь можно заменить на любой):
python3.13 -m venv /private/var/folders/hn/d7dw50jn3pb250mptnv1hmjc0000gn/T/opencode/kokoro-exp/venv

# зависимости эксперимента:
<env>/bin/pip install mlx-audio misaki num2words spacy phonemizer soundfile
<env>/bin/python -m spacy download en_core_web_sm
brew install espeak-ng          # библиотека, которую требует phonemizer

# образцы по умолчанию + Samantha для сравнения:
<env>/bin/python tools/kokoro_voice_samples.py --with-say --out ~/Desktop/kokoro-voices

# свои фразы:
<env>/bin/python tools/kokoro_voice_samples.py --with-say "Фраза 1." "Фраза 2."
```

Зависимости эксперимента (Python 3.13, arm64): mlx-audio 0.6.4,
mlx 0.32.4, misaki 0.7.4, num2words 0.5.14, spacy 3.8.18
(+ модель `en_core_web_sm` 3.8.0), phonemizer 3.6.0, soundfile 0.14.0,
espeak-ng 1.52.0 (Homebrew). Примечания: `misaki` не декларирует
`num2words`/`spacy` как зависимости (без них `misaki.en` не импортируется);
`misaki.espeak` требует `phonemizer` и библиотеку espeak-ng; `soundfile`
нужен для чтения AIFF, который пишет `say` (`aifc` удалён в Python 3.13).

Модель: **mlx-community/Kokoro-82M-bf16** (Hugging Face; веса в кэше
`~/.cache/huggingface`, ~312 MiB bf16 + voice-pack'и, вне репозитория;
первый запуск скачивает). На Hub репозитория `mlx-community/Kokoro-82M`
больше нет (401 Repository Not Found) — рабочий MLX-порт это `Kokoro-82M-bf16`.
Британская фонетизация в установленной версии задаётся
`KokoroPipeline(lang_code="b")` (алиас `en-gb`), G2P — misaki с
`british=True`.

### Qwen3-TTS-12Hz-1.7B-VoiceDesign (мягкий британский голос)

Сравнение с любимым Kokoro-голосом `bf_emma`: два описания голоса
(варианты A и B, «мягкий/светлый южнобританский женский тембр») на тех
же четырёх репликах. Реплики генерируются отдельно (по одной на вызов
`generate_voice_design`), чтобы проверить сохранение тембра и акцента
между ответами; на вариант — один WAV с паузами.

```bash
# то же экспериментальное окружение, что Kokoro; доп. пакеты не нужны
# (модуль qwen3_tts входит в mlx-audio):
<env>/bin/python tools/qwen3_voice_design_samples.py --out ~/Desktop/kokoro-voices

# свои описания/фразы (имена выходных файлов — --prefix,
# чтобы не затереть уже готовые образцы):
<env>/bin/python tools/qwen3_voice_design_samples.py \
    --instruct-a "..." --instruct-b "..." --prefix qwen3_vd_v2 \
    "Фраза 1." "Фраза 2."
```

Модель: **mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16**
(Hugging Face; bf16, 24 kHz; веса в кэше `~/.cache/huggingface`,
~4.2 GiB, вне репозитория; первый запуск скачивает). Образцы
`qwen3_vd_A.wav` / `qwen3_vd_B.wav` пишутся рядом с `bf_emma.wav`
(по умолчанию `~/Desktop/kokoro-voices`) — вне Git.

### Низкий «бархатный» регистр (четыре варианта A–D)

`tools/qwen3_low_register_samples.py` — четыре голоса: одно общее
описание (мягкое, тёплое, бархатное звучание, южнобританский акцент,
«терпеливый преподаватель») + у каждого своё описание регистра.
Реплики — отдельно (по одной на вызов), на вариант один WAV с паузами
0.6 c; громкость партии выровнена по RMS; высота — как у модели
(без постобработки):

```bash
<env>/bin/python tools/qwen3_low_register_samples.py \
    --out ~/Desktop/qwen-voice-low-register
```

Исходный Qwen-образец (`qwen3_vd_A.wav`) копируется рядом для
сравнения (`--reference`, `--skip-reference`).

### Понижение высоты готовых образцов (Rubber Band)

`tools/pitch_shift_voices.py` — для каждого готового WAV версии:
исходная + ниже на 1 и 2 полутона (или свой список `--semitones`).
Обработка существующих записей, без повторного синтеза:

```bash
brew install rubberband   # движок, если ещё не установлен

# A и B: orig / −1 ст / −2 ст рядом (6 WAV), громкость партии выровнена:
<env>/bin/python tools/pitch_shift_voices.py \
    ~/Desktop/kokoro-voices/qwen3_vd_A.wav ~/Desktop/kokoro-voices/qwen3_vd_B.wav \
    --outdir ~/Desktop/qwen-voice-comparison
```

Метод: Rubber Band R3 (`-3`), `-F` — сохранение формантов (понижение
не делает голос глухим), `-t 1` — длительность, темп и паузы
сохраняются точно; громкость партии выравнивается по RMS к самой
громкой версии (линейное усиление, пик ≤ 0.98). Без эквализации
и компрессии. Имя выходного файла: `<база>_orig.wav`, `<база>_m1.wav`,
`<база>_m2.wav` (mN — ниже на N полутонов). Результаты — вне Git.

### Сохранность выбранного голоса D на новых репликах (2 способа)

Выбранный голос — вариант D (`qwen3_low_D.wav`). Чтобы новые ответы
озвучивались тем же голосом, на 4 НОВЫХ репликах (короткая, короткая,
средняя, длинная; одна реплика — отдельный вызов модели; на способ —
один WAV с паузами 0.6 c + по файлу на реплику) проверены два способа:

* **voice_design** — модель VoiceDesign + исходное описание голоса D
  (повторное описание того же голоса);
* **reference** — модель Base (`...-1.7B-Base-bf16`) + одна чистая
  реплика D (`qwen3_D_ref_phrase.wav`, получена разбивкой
  `qwen3_low_D.wav` по паузам; точный текст
  «Hi! How was your day? Tell me one thing you enjoyed.»).

```bash
# то же экспериментальное окружение; Base-модель при первом запуске
# скачивается (~3.6 GiB) и кэшируется в ~/.cache/huggingface:
<env>/bin/python tools/qwen3_voice_consistency_check.py --method voice_design
<env>/bin/python tools/qwen3_voice_consistency_check.py --method reference
```

Измерено (M1, модель из кэша; синтез — одна реплика на вызов):

| Замер | voice_design | reference |
|---|---|---|
| загрузка модели (из кэша) | 3.41 c | 3.40 c |
| короткая реплика | 1.58 c | 4.47 c |
| длинная реплика | 6.06 c | 5.00 c |
| 4 реплики суммарно | 12.03 c | 14.22 c |
| F0_median (грубый замер) | 193.5 Hz | 212.4 Hz |
| log-mel расстояние до D (грубее) | 0.89 | 6.41 |

Объективные метрики (медиана F0, log-mel расстояние) показывают, что
**voice_design** ближе к выбранному образцу D (189.0 Hz; внутренний
ориентир — различие реплик одного голоса ≈ 1.29), **reference** —
заметно выше и дальше. Это ориентир: **финальное решение — на слух**
(файлы в `~/Desktop/qwen-voice-low-register/`: `qwen3_D_vd_new.wav`,
`qwen3_D_ref_new.wav`, `qwen3_D_ref_phrase.wav`, `qwen3_low_D.wav`).
Веса и WAV — вне Git.

Следующий шаг: в `qwen3_D_vd_p4.wav` (длинная реплика voice_design)
нравятся произношение, голос и тембр — она взята как референс
Base-режима. Точный текст реплики (из `DEFAULT_PHRASES` скрипта,
«That was a really good answer. You explained your idea, gave an
example, and kept your rhythm natural.») передан как `ref_text`
и проверен расшифровкой (faster-whisper large-v3: все 18 слов
совпадают, нет обрывов — речь 0.05–7.20 c, естественная тишина на хвосте):

```bash
<env>/bin/python tools/qwen3_voice_consistency_check.py --method reference \
    --ref-audio ~/Desktop/qwen-voice-low-register/qwen3_D_vd_p4.wav \
    --ref-text "That was a really good answer. You explained your idea, " \
               "gave an example, and kept your rhythm natural." \
    --prefix qwen3_p4_ref
```

Результат — `qwen3_p4_ref_new.wav` + `qwen3_p4_ref_p1…p4.wav`
(рядом — p4-референс и прежняя `qwen3_D_ref_new.wav` для сравнения).
Загрузка модели 3.43 c; синтез 3.67–6.05 c на реплику (17.15 c на 4).
F0_median 195.1 Hz (прежний референс — 212.4; p4 — 206.9);
log-mel расстояние к p4: 0.84 против 4.47 у прежней сборки.
Решение — на слух.

### Интеграция Qwen3-TTS в приложение (подключена, по умолчанию включена)

`companion/tts_qwen3.py` — озвучивание ответов Qwen3-TTS (MLX) с тем же
публичным API, что у `TtsSynth` (`synthesize`/`shutdown`, сигналы
`state_changed`/`reply_ready`/`failed`, владелец своих временных WAV):
синтез — в фоновом потоке (UI не блокируется), модель грузится лениво
на первом ответе, `mlx_audio` импортируется лениво — приложение и тесты
работают без mlx-audio и без весов. Режимы: `reference` (Base-модель +
реплика-референс p4 + её точный текст; **по умолчанию**) и
`voice_design` (описание голоса D).

* `AppConfig.tts_engine`: `"qwen3"` (по умолчанию) | `"say"` (резерв);
  `tts_qwen3_method`: `"reference"` (по умолчанию) | `"voice_design"`;
  голос — референс p4 (`tts_qwen3_ref_audio`/`tts_qwen3_ref_text`);
* референс хранится в постоянной папке данных приложения
  (`companion/app_data.py`), восстановление —
  `tools/install_tts_reference.py`; при отсутствии файла — понятная
  ошибка ДО загрузки модели;
* `build_tts(config)` (`companion/audio_controller.py`) — выбор движка;
  фасад работает с любым синтезатором через общий API (состояние,
  автозапуск, «Повторить ответ», порядок shutdown — не изменились);
  `reference` без пары «файл + текст» — явная `ValueError`;
* установка в рабочий `.venv`: `pip install ".[qwen3-tts]"` — реально
  установлено (чисто добавочный набор: mlx-audio 0.6.4, transformers
  5.22.1 и утилиты; mlx 0.32.4, numpy 2.5.4, PySide6, av, mlx-whisper,
  faster-whisper не меняются; импорты сосуществуют в одном процессе);
* память (M1, 16 GiB): веса Qwen3 ~4 GiB + STT whisper-large-v3
  ~3 GiB — вместе влезает, но с запасом небольшой;
* тесты: `tests/test_tts_qwen3.py` — оффлайн, подменённый синтезатор
  (без mlx-audio, без весов): успех, смена незавершённого, повтор,
  ошибки, занятое аудио, закрытие, `build_tts`, отсутствие референса;
* реальная проверка: `real_tts_check.py` (см. «Реальная многоцикловая
  проверка»).
